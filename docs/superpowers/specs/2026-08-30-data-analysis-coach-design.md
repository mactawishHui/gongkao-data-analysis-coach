# 公考资料分析教练设计

## 1. 目标与边界

在当前工作区内创建一个可被 Codex 自动发现的“公考资料分析教练”技能。它以文件夹中的 10 份《资料系统班》随堂笔记为核心依据，支持文字题、截图题和 PDF 页面的解题、陪练、诊断、专项练习、错题复习与进度定位。

首版只声称覆盖行测资料分析，不把缺少本地资料的言语、判断、数量、常识或申论伪装成已覆盖内容。遇到范围外题目时可以用通用能力回答，但必须明确不计入本知识图谱的资料覆盖率。

## 2. 成功标准

助手必须同时满足：

1. 准确抽取时间、对象、指标、单位、口径、图例、问法和选项。
2. 数据不完整或图片模糊时指出缺口，不猜数。
3. 给出可追踪的题型定位、关系式、每步理由和独立验算。
4. 以考试速度为目标，优先寻找能稳定选出选项的简便方法。
5. 每题总结同类规律、适用边界、常见陷阱和一道迁移思考。
6. 取得明确写入授权后，将作答真实写入本地错题/练习数据库，并能回读；仅陈述答案、用时或信心不等于授权。
7. 按知识节点归类，展示前置与后继知识，形成整体结构。
8. 能根据薄弱节点、到期错题和迁移需要生成专项练习。
9. 用样本量、置信区间、正确率、速度、方法质量、稳定性与保持度定位进度；证据不足时明确显示“未充分评估”。
10. 所有确定性脚本、知识资产和关键工作流均有自动化或前向测试证据。

## 4. 七种模式

| 模式 | 触发意图 | 主要输出 |
|---|---|---|
| 解题 | “这题怎么做/选什么” | 审题卡、最快可靠法、必要精算、验算、同类总结 |
| 陪练 | “提示我但别公布答案” | 分级提示，等待用户作答后再讲解 |
| 记录 | 用户明确要求记录，或肯定回答本轮写入确认 | 数据库写入回执、错误归因、复习安排 |
| 专项练习 | 指定知识点/题量/难度 | 经脚本验证的题组或受模板约束的题组 |
| 诊断 | “测测我水平” | 覆盖不同主干节点的诊断卷和定位报告 |
| 错题复习 | “复习到期错题” | 到期题、遮蔽答案、作答后更新间隔 |
| 进度 | “我学到哪了/薄弱点” | 多维统计、置信区间、知识图谱覆盖、下一步建议 |

## 5. 审题与解题协议

### 5.1 审题卡

每题先确认：

- 时间：现期、基期、同比/环比、累计/当期、起止区间。
- 对象：地区、行业、部分、整体、集合包含关系。
- 指标：量、率、比重、百分点、倍数、平均数、贡献率。
- 单位：元/万元/亿元、吨/万吨、人/万人以及月/季/年。
- 目标：求值、比较、排序、计数、判断能否推出。
- 选项：正负、量级、相邻间距和所需有效位数。
- 数据质量：图例遮挡、坐标截断、文字与图表口径冲突。

任一关键字段不可辨时先请求补图或澄清；已足以排除并唯一作答时无需为了形式补齐无关数据。

### 5.2 速度优先的方法路由

每题按以下顺序尝试，命中即停止：

1. **定性秒杀**：正负、增速大小、比重趋势、混合居中、包含/容斥、单调性。
2. **范围与量级**：数量级、上下界、选项区间、倍数关系、增量“大大则大”。
3. **特征数字**：尾数法、高位叠加、整数基准值、“21/12”分段。
4. **常用分数与份数**：小分互换、415 份数法、十字交叉、线段法。
5. **拆分与假设分配**：50%/10%/5%/1% 拆分，增长量近似，误差方向修正。
6. **截位直除**：由选项间距决定保留位数；能不截位时不机械截位。
7. **完整精算**：仅在相邻选项过近、估算决策余量不足或用户明确要求时使用。

### 5.3 估算安全规则

快算答案必须同时写清：

- 用了什么近似。
- 近似使结果偏大还是偏小。
- 当前估值与相邻选项的决策余量。
- 为什么误差不足以跨越选项边界。
- 在什么更密的选项设置下该方法会失效。

不得只写“约等于”后跳到答案。若无法证明估算安全，升级到更精细的方法。

### 5.4 默认解答结构

1. 结论与预期用时。
2. 审题卡。
3. 题型定位及识别信号。
4. 最快可靠方法。
5. 估算安全性或误差方向。
6. 必要时补充稳妥方法/精算。
7. 独立验算与单位复核。
8. 同类题总结、失效边界和迁移题。
9. 知识图谱位置。
10. 用户提供作答数据且明确授权写入时，返回真实写入回执和复习计划；未授权时只询问是否记录。

## 6. 知识体系

顶层依赖为：

```text
速算基础 speed
├─ ABRX 四量关系 abrx
│  └─ 增长率体系 growth
│     ├─ 比重体系 share
│     │  └─ 比较类 compare
│     ├─ 混合与十字交叉 mixture
│     ├─ 平均、倍数与年均 average
│     └─ 特殊考点 special
└─ 审题陷阱 trap
```

知识图谱使用稳定 ID，至少覆盖：

- `speed.*`：尾数、高位叠加、基准值、分段、分数互换、拆分、直除、415、假设分配。
- `abrx.*`：A/B/R/X 一般、间隔、差值、组合和预测。
- `growth.*`：一般、间隔、比值、乘积增长率。
- `share.*`：现期、基期、隔级、趋势、比重差、比值差。
- `compare.*`：分数、增速、基期、增量、替代比较、追及、查找后计算。
- `mixture.*`：混合定性、三浓度排序、十字交叉、量比和反求第三率。
- `average.*`：平均数、倍数、年均增长量、年均增长率。
- `special.*`：拉动增长、增量贡献率、容斥。
- `trap.*`：时间、合计、首年、单位、排序、图文口径、同比环比、倍数措辞、进出口、累计、月均和 1-2 月合并。

每个节点包含标题、父节点、前置节点、来源页、识别信号、公式引用、速算方法和错误代码。首版另为 10 个核心计算/定性节点提供确定性参数化模板；其余节点使用到期错题、讲义真题或受题型协议约束且独立复核的练习，不声称已由参数生成器验证。

## 7. 正确性与来源策略

答案证据优先级：

1. 数学恒等式或确定性脚本复核。
2. 题目原始数据和图表口径。
3. 讲义解析。
4. 讲义标答。

已确认的勘误必须高于讲义原标答：

- 第六讲 PDF 第 2 页例 21：正确答案 C，讲义标 B。
- 第六讲 PDF 第 9 页例 29：标答 A 正确，解析第③步“可选 B”应为“可选 A”。

所有知识结论保留讲次与 PDF 页码；文本抽取与渲染冲突时以页面视觉复核为准。

## 8. 持久化数据模型

SQLite 数据库存放在工作区 `.gongkao-study/study.sqlite3`，不写入源 PDF。当前 schema v3 在 `schema_meta` 保存版本、`owner=gongkao-data-analysis-coach` 应用标记和每库唯一 `instance_id`；后者用于防止已验证写入对象被另一同类库替换。标记只表明数据库用途和实例，不改变用户对本地文件的所有权。

核心表：

- `attempts`：题目摘要、题源、用户答案、正确答案、对错、用时、信心、难度、模式、解析置信度、所用方法、推荐方法、方法质量。
- `attempt_tags`：一次作答对应的一个或多个知识节点。
- `attempt_errors`：审题、时间、口径、单位、定位、建模、公式、计算、精度、方法低效、讲义冲突等错误。
- `reviews`：复习到期日、间隔、轮次、状态和复习结果。
- `sessions`：为后续分组会话元数据预留的表；首版掌握度只从真实 `attempts` 及其主标签、复习记录推导，不把空会话表作为能力证据。
- `schema_meta`：应用标记与数据库版本。

读取与写入严格分离。`attempt`、`mistakes`、`due`、`progress` 和数据库侧的 `export` 以只读方式打开现有 v3，不创建目录/文件、不迁移、不修复、不切换日志模式；缺库或 v2 只返回错误。`init` 是显式创建/迁移；已获授权的 `record`、`review` 可把结构完全匹配的已知 v2 作为写入前置迁移。外来 SQLite、错误 owner、缺表/多表、列异常、未来版本或损坏库失败关闭，原库与 sidecar 保持不变。

每次 CLI 调用只输出一个 JSON 文档；`--help` 也以 `ok=true`、`object_id=help` 和 `help` 字段返回。`record` 成功回执包含数据库路径、attempt ID、标签及必要的复习时间；`review` 返回新 review ID 和间隔；`init` 返回 schema；`export` 返回目标路径和计数，不能笼统要求所有动作都有题目标签。记录载荷经 `record --json-file -` 的标准输入传入，不把用户文本拼进 shell。数据库和导出目标必须留在当前工作区，导出默认不覆盖；活动主库以及其 `-wal/-shm/-journal` 即使指定 `--force` 也不得作为导出目标。

## 9. 错题与复习

答错、高信心错误、方法明显低效或讲义冲突均可进入错题本。一次错题至少记录：

- 原题可识别摘要与来源。
- 用户答案、正确答案、用时和信心。
- 主/次知识标签。
- 根因错误码，不把所有错误笼统归为“粗心”。
- 最快可靠法、个人错误路径和一句订正规则。
- 复习日期。

复习间隔按结果更新：首次错题次日复习；复习“不会/仍错”重置为 1 天；“费力答对”为 3 天；“熟练答对”按 1、3、7、14、30 天阶梯推进。高信心错误额外标为高优先级。

## 10. 进度与准确定位

每个知识节点输出六个维度：

1. 正确性：正确数/有效作答数及 Wilson 90% 区间。
2. 速度：中位用时、最近中位用时、有效目标用时差和目标来源计数。
3. 方法效率：最优/可接受/低效方法占比。
4. 稳定性：最近窗口正确率与全量正确率差、同错复发率。
5. 迁移：相邻或混合题正确率。
6. 保持度：到期复习通过率。

状态标签：

- `未评估`：0 次有效作答。
- `样本不足`：1-4 次；只报告观测值与宽区间，不给确定掌握结论。
- `学习中`：样本至少 5，但正确性、速度或稳定性未达标。
- `基本掌握`：样本至少 8，最近正确率至少 80%，方法低效不超过 30%，且至少一次间隔复习通过。
- `稳定掌握`：样本至少 15，最近正确率至少 90%，达到目标速度，方法低效不超过 15%，迁移题和两次间隔复习均通过。

总体进度按知识节点和前置权重汇总，同时显示“已评估节点比例”；不得用少量已做题目的 100% 正确率代表整体 100% 掌握。只有高可追溯、解析置信度未填或至少 0.90、且不含 `missing_question` / `parse_uncertain` 的主标签作答才进入全部进度维度；其他记录仅保留为可检索、可复习的诊断线索。

v3 用 `target_duration_source=default|explicit|legacy_unknown` 区分目标来源。新作答省略目标时有效目标为 45 秒；显式目标保留。旧 v2 的列默认和记录均为 60 秒时无法恢复当年的显式性，故保留原值供审计、标 `legacy_unknown`，但进度保守按有效 45 秒计算，避免虚高速度定位。

## 11. 专项练习与诊断

助手编排练习时默认比例为 40% 到期错题、40% 当前薄弱节点、20% 相邻迁移；这不是单次 `generate` 命令自身完成的混合。用户明确指定知识点时在指定范围内保持同样结构。首批模板的难度依据必须由目录逐题公开：数值题通过选项间距控制，定性趋势题通过可见率差信号控制；不得笼统声称同时改变了未实际改变的数据复杂度。

参数化题必须由脚本先生成真值，再生成包含唯一正确答案的选项，并复算验证。数值模板从题面可见十进制数据独立重算，正确值和选项使用 `Decimal ROUND_HALF_UP` 的通常十进制四舍五入；负半位同样远离 0，不使用二进制浮点半偶舍入。首版确定性目录覆盖 10 个核心节点；超出目录时必须明确说明生成器未覆盖，优先取真实错题/讲义真题，或由 Codex 根据对应题型协议生成并把结构化数据交给公式引擎复核后再展示。`share.trend` 模板为保证三档难度确实由可见率差区分，只生成明确上升/下降；相等情形另用讲义或独立核验题训练。生成器的 `quick_hint` 只是教学提示；除非另有估值、偏差方向和误差界推导，真值/唯一选项验证不得冒充快法安全验证。

诊断卷覆盖速算、ABRX、增长率、比重、比较、混合、平均年均和特殊陷阱，初次建议 12-16 题；诊断只在获得写入授权并成功落盘后，基于实际作答更新跨会话定位。

## 12. 错误处理与隐私

- 图片无法辨认：列出不可辨字段并请求更清晰局部图。
- 用户只给答案未给题：不创建虚假题目。即使用户授权，若不能由其他可靠证据确认具体可评估主节点和真实对错，也不写入作答表；两者都已确认时才可记录匿名摘要并标低可追溯性。
- 知识标签不存在：脚本拒绝写入并列出可用标签。
- 数据库不可写：报告真实错误，不声称已记录。
- 数据库损坏或用途不匹配：保留主库与现有 sidecar，只返回只读诊断错误；普通导出失败，不自动认领、修复、降级或覆盖。
- 所有学习数据仅保存在本地工作区；新库先在内存中构造完整镜像，再写入同目录随机 `0600` 暂存文件，并用系统原子“仅目标不存在时重命名”发布。成功后只保留单一主路径，任何具有第二个硬链接的数据库均拒绝打开；可写打开前后还以绑定目录句柄核对现有 `-wal/-shm/-journal` 的类型、单链接状态与 inode 身份。发布前失败时暂存文件可能保留，以避免对已被置换的路径做破坏性删除。删除状态时应删除整个 `.gongkao-study/`。记录载荷用纯函数预检，只读一致性快照从绑定文件句柄捕获主库/WAL 字节，在内存中验证提交帧并反序列化，不产生临时题目文件。导出保持已写临时文件句柄到发布后，以 inode 校验内容身份并原子发布，失败时不按未经条件绑定的路径删除。不联网、不上传。

## 13. 测试与验收

### 确定性测试

- 公式：ABRX、间隔/比值/乘积增长率、比重、贡献率、Wilson 区间。
- 数据库：初始化、schema v3 owner 与 instance、合法 v2 迁移、旧 60 秒有效目标 45 秒、重复写入、标签校验、错题检索、复习更新、导出；缺库只读不创建，v2 只读不迁移，外来/损坏/错 owner/错 instance 失败关闭，三个 sidecar 即使 `--force` 也不能覆盖。
- 练习：固定 seed 可复现、正确选项唯一、题面数据无隐藏精度、十进制负半位舍入正确、解答独立复算一致。
- 进度：样本不足不误判，状态阈值和时间统计正确。
- 知识资产：ID 唯一、前置节点存在、来源页合法、勘误可检索。

### 前向行为测试

使用全新代理测试：

1. 讲义标答错误且用户高信心选错时，能否坚持数学复核、标记讲义冲突并真实落盘。
2. 仅 2 题全对时，能否拒绝虚假精确定位。
3. 45 秒计算题是否先给安全快法、偏差方向和失效边界。
4. 模糊图表是否停止猜数。
5. 同一题能否给出同类总结、迁移和知识图谱位置。
6. 专项练习答案是否全部经脚本验证。

通过条件是：自动测试无失败；技能校验通过；根帮助与子命令帮助均为单 JSON；数据库写入可回读、只读前后主库与 sidecar 字节集合一致；至少三类前向场景满足协议；要求覆盖审计无缺口。

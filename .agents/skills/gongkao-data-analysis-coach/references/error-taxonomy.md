# 错误根因词典

错误记录必须使用下面的 canonical registry。错误答案至少要有一个可追溯根因；“粗心”“不会”“算错了”都不是合法错误代码，因为它们不能决定下一步训练。未知或拼错的代码应被拒绝，不能部分写入。

## Canonical 错误代码

| 错误代码 | 根因 | 识别证据 | 纠正动作 | 复发预防 |
|---|---|---|---|---|
| `wrong_period` | 取错现期、基期、同比/环比、累计/当期或起止区间 | 公式可算，但代入的年份、月份或区间不是题目所问 | 画时间轴，分别标 A、B 与间隔数后重新取数 | 每题先圈时间词；年均题单独数间隔，累计题先判断是否需作差 |
| `wrong_scope` | 对象、集合或统计口径不一致 | 分子分母来自不同地区、行业、总体或包含层级 | 写出“部分属于哪个整体”的集合链，再定位同口径数据 | 审题卡固定记录对象与集合包含关系 |
| `wrong_indicator` | 把量、率、比重、百分点、倍数或平均数当成另一指标 | 计算结果量纲与题问不一致，或把“最多”当“最快” | 用一句关系式定义目标指标并补上单位 | 计算前写目标是求值、比较、排序还是变化方向 |
| `wrong_unit` | 忽略元/万元/亿元、吨/万吨、人/万人等换算 | 数量级与选项相差 10、100、10000 倍 | 把全部数据先统一到同一单位，再计算 | 在每个数旁写单位；运输、进出口和面积题优先做量级检查 |
| `wrong_wording` | 误解增加、增长、降低、降幅、是几倍、多几倍或排序方向 | 公式数值正确但选项映射错误，或最终顺序反了 | 把题问改写成数学符号，如“多几倍=B/A-1” | 交卷前复读目标措辞与排序方向，不只复核算式 |
| `wrong_denominator` | 增长率、比重、平均数、拉动或贡献率的分母选错 | 分子含义合理但结果方向/量纲异常；常见为增长率除以现期 | 写出完整定义式并给分母命名，再代数 | 记关系而非孤立口诀：增长率分母是基期，比重分母是对应整体 |
| `reversed_rates` | 比值/基期比重修正时颠倒分子率与分母率 | 定性方向与“分子长得更快则比值上升”冲突 | 先标 `r分子`、`r分母`，再按关系式代入 | 每次精算前先独立判断正负，精算方向必须与定性一致 |
| `missing_cross_term` | 间隔或乘积增长漏掉 `r1×r2` | 直接把两段增速相加，尤其在选项接近时偏离 | 恢复 `(1+r1)(1+r2)-1` 并保留交叉项符号 | 看到连续两段或两个乘积因素，先写乘法恒等式 |
| `sign_error` | 下降量、负增长、差值或反向变化漏负号/符号反转 | 数值绝对值接近但上升下降相反，或负增量被当正数排序 | 在代入前写每个量的正负，结果后做方向复核 | 比较类保留有符号值；不使用绝对值代替增长量 |
| `formula_error` | 选择了不适用的公式或代数变形错误 | 数据口径正确、运算也正确，但关系模型与题意不符 | 回到定义式，从量之间的实际关系重新推导 | 先识别一般、间隔、比值、乘积或混合，再选公式 |
| `arithmetic_error` | 在正确公式和数据上发生加减乘除错误 | 独立复算同一表达式得到不同结果 | 用另一条路径复算，并定位第一处数值分叉 | 保留中间量和单位；关键结论至少做一次反乘或数量级验算 |
| `precision_error` | 截位、四舍五入或有效位数不足 | 近似区间触及相邻选项边界，增加位数后选项改变 | 恢复更多原始位数并重新评估误差 | 由选项间距决定保留位数，能不截位时不机械截位 |
| `unsafe_estimate` | 使用近似却没有可证明的误差方向与决策余量 | 只写“约等于”，或可能跨越选项中点 | 给出偏大/偏小、误差上界和最近选项边界；不足则精算 | 快算前先看选项差，答案后固定写安全条件与失效条件 |
| `method_mismatch` | 方法虽可能算出答案，但与信号、数据或选项结构不匹配 | 负增长硬用繁琐假设分配、宽选项长除或密选项粗估 | 按定性→范围→特征数字→份数→拆分→直除→精算重选路线 | 记录推荐方法与实际方法；重复低效时做同节点限时训练 |
| `source_conflict` | 讲义标答/解析与题目数据、数学恒等式或页面视觉证据冲突 | 独立复算与原始数据相互一致，但来源文字给出另一结论 | 按证据优先级复核并引用勘误记录，不把冲突归咎于学习者 | 命中已知冲突先查 `errata.md`；新冲突先视觉核页再确定性复算 |
| `missing_question` | 只提供答案、时间或信心，没有完整题干/材料 | 无法确认时间、对象、指标、选项或来源，追溯性为低 | 请求题干或截图；若不能独立确认具体主节点和真实对错，则不持久化为作答证据 | 写入前确认问题与来源；无题干时不推断具体知识缺口 |
| `parse_uncertain` | OCR、图例、坐标、表头或选项解析置信度不足 | 关键数字有多种读法、文字与图表不清，无法唯一定位 | 请求清晰补图或人工确认关键字段；歧义影响主节点或判分时不持久化 | 页面视觉优先于文本抽取；只保存已被独立确认的评分与分类事实 |

## 主因、次因与错误路径

一次作答可以有多个错误代码，但必须区分：

- **主因**是最早发生、修复后能阻断后续错误的根因，放在 `errors` 首位，并写入 `error_path` 的起点。
- **次因**是主因之后真实发生的派生问题，按发生顺序记录；不要为了显得完整而罗列所有可能代码。
- 例如把“万吨”当“吨”后又加错，主因是 `wrong_unit`，次因才是 `arithmetic_error`；若单位修正后运算其实无误，就只记主因。

`error_path` 应写成可复现链条，例如：“忽略题干问基期 → 直接拿现期作分母 → 结果落入现期陷阱项”。它描述事实，不使用“粗心”作解释。

## 三类证据异常的边界

- `source_conflict`：只有题目原始数据/图表口径与数学复核支持同一结论，而讲义解析或标答冲突时使用。即使用户独立答对，也可记录来源风险；这不是用户知识错误。
- `missing_question`：题干、材料或选项没有提供，无法还原作答条件时使用。它可以作为本轮诊断标签；只有另有可靠证据同时确认具体可评估主节点和真实对错时，才可保存匿名摘要，否则不写入作答表。
- `parse_uncertain`：题目已提供，但 OCR、图表或截图的关键字段存在歧义时使用。关键字段不足以唯一作答就请求澄清，不猜数；若其余证据足以唯一排除，须明确只依赖了哪些已确认字段。

三者可与知识根因并存，但只有实际证据支持时才记录。例如来源本身正确、只是用户看错，不能写 `source_conflict`；没有题干与题干模糊也不能混为同一个代码。

## 纠正规则的形成

`correction_rule` 从主因提炼，写成下一题可执行的一句话，结构为：

> 触发信号 → 必做动作 → 独立检查 → 升级条件

示例：主因为 `reversed_rates` 时，可写“看到比值变化，先标分子率与分母率，用二者差定正负，再代公式；方向不一致就停止并重算”。主因为 `unsafe_estimate` 时，可写“近似后标偏差方向和误差上界，比较最近选项中点；余量不足立即精算”。规则不能包含本题答案，也不能只是“下次认真”。

## 复习与优先级

存储层按以下确定规则安排：

1. **安排复习**：答案错误，或方法质量为 `low`，或错误中含 `source_conflict`，任一条件成立即在 1 天后创建复习。因此来源冲突即使答对也会进入错题/复核队列。
2. **高优先级**：只有“答案错误且作答信心为 4 或 5”自动标为 `high`；这表示高信心错误暴露了稳定误解。其他情况默认为 `normal`，不因代码名称自动升高。
3. `missing_question`、`parse_uncertain` 若导致无法可靠判分或无法定位具体可评估主节点，应先补充证据且不调用 `record`。即使评分与主节点由其他证据确认后把记录留作错题/复习线索，只要仍含这两个代码就不进入掌握度、覆盖率或其他进度统计。
4. 正确答案若方法不低效、且没有来源冲突，不会仅因为附带其他诊断代码自动安排复习。需要专项训练时，应把真实方法质量或判分结果记录准确，不能滥用代码触发日程。

复习记录内部保留主节点、主因、`error_path` 和 `correction_rule`，但首次 `due` 只返回题干、安全的分类代码和 `review_id`；用户重做后再读取完整记录进行订正。复习后检查的是规则能否迁移，而不是是否记住原选项字母。
